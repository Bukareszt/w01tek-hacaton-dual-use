<objective>
**As a** Wojtek developer working in a public repository, **I want to** configure a model vendor
without ever writing a credential into a tracked file, **so that** the experiment can be pushed,
cloned onto the dev box and read by anyone with no risk of leaking a key or the identity of private
infrastructure.

This slice adds the configuration surface Phase 2 will actually use, and the automated test that
makes the hygiene rule enforceable rather than aspirational.

Purpose: FOUND-04 in full — keys enter only through the gitignored `.env`, the committed template
carries placeholders, and a test rejects secret-looking values in tracked config.
Output: `config.toml`, `wojtek_rai/config.py`, two model-free tests, `run.sh` env passthrough, and
an extended `.env.example`.
</objective>

    Write `experiments/wojtek_rai_v1/wojtek_rai/config.py` exposing `config_path`,
    `load_experiment_config` and `required_env_vars`.

    `config_path()` anchors on the module's own location (`Path(__file__).resolve().parent.parent`)
    rather than the working directory, and returns the absolute path to the experiment's
    `config.toml`. This is the whole point of the module: RAI's own loader opens a bare relative
    filename against whatever the process working directory happens to be, and the container's
    default working directory is the ROS workspace root, not the experiment. Any code in this and
    later phases that needs the config goes through this function, or passes its result explicitly
    to RAI's loader. Say so in the module docstring.

    `load_experiment_config()` parses that path with `tomllib` from the standard library and
    returns the mapping. No RAI import, no network, no environment access — this keeps the module
    importable and testable with nothing installed but the standard library.

    `required_env_vars(vendor)` maps a vendor name from the config's vendor table to the tuple of
    environment variable names that vendor needs: the OpenAI vendor needs `OPENAI_API_KEY`; the
    Google vendor needs `GOOGLE_API_KEY`; the AWS vendor needs `AWS_ACCESS_KEY_ID`,
    `AWS_SECRET_ACCESS_KEY` and `AWS_SESSION_TOKEN`; the Ollama vendor needs none. Unknown vendors
    raise with the offending value in the message. The function returns names only and must never
    read, log or return a value.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| gitignored `.env` → tracked tree | Credentials must cross into the process environment without ever crossing into a tracked file |
| developer terminal / CI log → public record | Anything `run.sh` prints can end up pasted into an issue, a commit message or `docs/VERIFICATION.md` |
| this repository → the public internet | The repository is public; every tracked byte is published |
| the experiment → an external tracing backend | Langfuse and LangSmith would receive prompts and completions if enabled |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-11 | Information Disclosure | A vendor or tracing credential committed into `config.toml` or `.env.example` | high | mitigate | The upstream config schema has no credential field at all and is committed verbatim; `test_no_secrets_in_config.py` scans every git-tracked file under the experiment plus `.env.example` with a compiled credential-shape regex and is proven fail-first against an introduced violation |
| T-01-12 | Information Disclosure | Private infrastructure identity (dev-box hostname, IP, login, SSH alias) written into a tracked file | high | mitigate | A second compiled regex in the same test scans for dotted-quad addresses, `user@host` forms and remote-shell invocations across the same file set, matching the enumerated public-repository rule in CLAUDE.md |
| T-01-13 | Information Disclosure | `run.sh` echoing a credential value into terminal output or a CI log | high | mitigate | Values are forwarded by name through the exec environment, never restated on a command line; shell trace is prohibited and grep-asserted absent; the `.env` source block is copied from the existing deployment script, which already follows this rule |
| T-01-14 | Information Disclosure | Prompts and completions leaving the machine through a tracing backend | low | accept | Both tracing switches ship false, which is upstream's default and this project's requirement; enabling tracing is Phase 2 work under FOUND-05, and no tracing host identity is committed |
| T-01-15 | Spoofing | An unknown vendor string silently selecting no credentials and producing a confusing downstream failure | low | mitigate | `required_env_vars` raises with the offending value rather than returning an empty tuple for anything but the Ollama vendor |
