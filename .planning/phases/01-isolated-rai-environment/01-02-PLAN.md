<objective>
**As a** Wojtek developer, **I want to** build RAI's ROS 2 message package from a pinned commit into
the experiment's own colcon overlay, **so that** the RAI import chain later phases depend on
resolves reproducibly and can never be rsynced to the physical robot.

This is an expansion slice on the tracer from plan 01-01: the same `run.sh`, the same container,
one more capability. `rai_interfaces` is not on PyPI, so it is the one dependency `uv.lock` cannot
pin — it needs its own pin and its own build path.

Purpose: close the second half of FOUND-02's reproducibility requirement (`rai_interfaces` at a
pinned commit) and make FOUND-01's "colcon overlay outside `ros/src`" concrete.
Output: `ros/rai_interfaces.repos` at a resolved commit SHA, a working `run.sh build`, and a guard
test over both.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| github.com → the container | `vcs import` clones third-party ROS message source into the experiment's overlay |
| apt / rosdep → the container | `rosdep install` pulls system packages this image does not ship |
| experiment overlay → `ros/deploy.sh` | Anything under `ros/src/` is rsynced to the physical robot |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-07 | Tampering | `vcs import` of `rai_interfaces` from a moving branch | high | mitigate | The `.repos` file pins a concrete 40-character commit SHA; `test_repos_pin.py` fails the suite if it degrades to `main`, `master` or a bare tag |
| T-01-08 | Elevation of Privilege | A built `rai_interfaces` landing under `ros/src/` and reaching the robot through `ros/deploy.sh` | high | mitigate | `colcon build --base-paths ros_ws` targets the experiment's own overlay; `test_repos_pin.py` asserts nothing matching `rai_interfaces` or `wojtek_rai_v1` exists under `ros/src/`; plan 01-04 adds the broader import-boundary guard |
| T-01-09 | Tampering | `rosdep install -y` pulling `nav2_msgs`, `vision_msgs`, `tf_transformations` and `portaudio19-dev` into the shared container | medium | mitigate | Scoped with `--from-paths ros_ws/src --ignore-src` so only the imported source's declared keys resolve; installed into the running container at build time, never baked into `ros/docker/Dockerfile` |
| T-01-10 | Repudiation | The exact commit actually built not being recoverable later | medium | mitigate | The resolved SHA is written into the committed `.repos` file and repeated in the plan SUMMARY, per D-09 and D-14 |
</threat_model>
