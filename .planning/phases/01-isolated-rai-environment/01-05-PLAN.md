<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| dev-box terminal output → tracked document | Pasted command output is the single most likely vector for private infrastructure identity to enter a public repository |
| operator's SSH configuration → this repository | The alias, host and login must stay on the operator's machine |
| an uncommitted working tree → the verification record | Evidence tied to no commit proves nothing reproducible |
| the standing authorization → the physical robot | The authorization covers install, build and test only |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-21 | Information Disclosure | A host name, address, login or alias pasted into `docs/VERIFICATION.md` from dev-box output | high | mitigate | The machine is named by role only; every pasted line is checked and redacted inline before commit; address-shaped and address-at-host-shaped patterns are grep-asserted absent; the identity scan from plan 01-03 covers `docs/` |
| T-01-22 | Repudiation | Evidence recorded against no identifiable commit, so a later reader cannot reproduce it | medium | mitigate | The commit SHA under verification is recorded in the document, and the dev-box run is made from a fetched commit rather than an rsynced tree |
| T-01-23 | Tampering | Two-machine support claimed from one machine's run | high | mitigate | The document has a section per machine; an incomplete run is written up explicitly as not discharged rather than omitted, and the plan SUMMARY carries the same statement |
